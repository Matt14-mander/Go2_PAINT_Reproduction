# Teacher 8600 视频与训练代码审查

审查对象：`logs/server_videos/teacher8600_nominal_01_20261025_215707_076335-step-0.mp4`。文件50fps、1280×720、约29.98秒；按24个时刻抽帧，并细看0.2、0.5、4、8、10.2秒。另结合用户此前同名 evaluation 的 Summary；该 Summary 不是本地读取的原始JSON。

结论：视频展示的是四份独立单机器人环境中的重复摆臂和转向，不能当作已学会交互力跟随。当前代码存在一个可复现的越界动作惩罚缺陷；另有小力课程下的奖励尺度、机械臂工作分布和高度目标适配问题。不能仅凭视频确定哪一项首先导致了PPO退化，也不能认定只修一项就能收敛。

## 视频证据

| 时间 | 可见现象 | 能支持的判断 |
|---|---|---|
| 0秒 | 首帧黑屏 | 录制/渲染预热，不作为动力学证据 |
| 约0.2秒 | 四个黄色载荷都接近竖直，机械臂明显伸展 | 启动阶段存在较大的载荷姿态变化 |
| 约0.5–8秒 | 载荷横摆，机器人不断改变朝向，平移与旋转混合 | 看到运动不能等同于跟随正确的受力参考 |
| 约10.2、20.2秒 | 四个环境重复接近启动时的姿态 | 与10秒episode、timeout自动重置一致，不应全部算成闪退/跌倒 |
| 全片 | 每台各自连接一块箱体，共四块 | 这是并行单机Teacher回放，非四机共享物体协作 |

对应用户提供的同名8600 nominal Summary：平均高层速度指令`[-1,-1,1.5]`，指令对参考RMSE约`[1.00,1.01,1.48]`，臂目标跟踪RMSE约1.00rad、默认姿态偏差约1.43rad，12次timeout、0次非timeout终止，最大采样倾角28.3度。因此本片不能描述为“反复跌倒”，应描述为“高层输出饱和、大幅摆臂/转向，但此固定工况未触发base接触终止”。

视频没有叠加真实外力向量，不能单凭图像判断跟随方向正确。名义配置`wrench_scale=.1`、1秒上升段下，约0.2秒时每轴外力上限仅0.8N、偏航力矩上限0.2Nm；早期大幅姿态变化更值得检查动作目标/重置瞬态，而非直接归咎于外力太大。

## 1. 已确认并修正：动作惩罚采用了限幅后的底盘值

相关代码：`mdp/transport_action.py::process_actions`、`mdp/transport_terms.py::action_cost`。

修正前，actor原始输出先被限幅到`[±1,±1,±1.5]`，`previous_hl`和动作代价随后都使用这个processed值。因此在零上一动作、零臂动作下：

| 原始底盘输出 | 执行指令 | 原动作代价 |
|---|---|---:|
| `[-1,-1,1.5]` | `[-1,-1,1.5]` | 6.375 |
| `[-100,-100,150]` | `[-1,-1,1.5]` | 6.375 |

不仅执行结果相同，越界幅度也没有额外动作代价。这是一个明确的学习盲区，与持续饱和现象吻合；它不等于“PPO必然饱和”的充分因果证明。

已改为保存上一控制步的**原始**9维动作，`action_cost`对原始动作计算幅度和变化率。相同对照下，第二行代价现在是第一行的10000倍。两项回归检查验证了越界区分、上一动作空间一致以及不与调用者Tensor别名。

这个修改不改变147/165观测、9维高层输出、247→12低层接口或执行目标；会改变后续训练的奖励。对旧checkpoint重新播放不会自动改好策略，旧训练曲线与修正后奖励数值不能直接混比。本轮没有更改奖励权重或启动训练。

## 2. 已确认的配置关系：小力课程削弱跟随收益，运动成本没有同步缩小

`force_tracking=-.02`、`torque_tracking=-.01`，当前使用`1-exp(-error²/.25)`成本，默认符号方向正确。`joint_dof=-.0002`却作用于全部18关节的`dq²+.00025*ddq²`。

以只要求`vx=.2`、其它参考为0为例，理想从静止改善为完美跟踪，平动项每秒最多改善约0.002957。**假设站立关节速度为0，忽略其它代价变化**，仅12个腿关节的RMS速度达到约1.11rad/s，`dq²`代价便足以抵消这项改善。`vx=.1`时阈值仅约0.572rad/s。真实是否发生，要用本轮TensorBoard奖励分项或rollout关节速度确认，不能将这些阈值视为已测量的实际速度。

此外，平动+转动跟踪成本在完整10秒episode内的最大**未折扣**累计差值约0.3，而一次非timeout终止为−50。量级相差约167倍。这不是实际PPO advantage的数值比较，折扣、终止时刻和归一化都会改变优化信号；也不证明终止惩罚错误，但说明不能只看总reward和存活率。

核对了[Isaac Lab RewardManager](https://raw.githubusercontent.com/isaac-sim/IsaacLab/v2.3.0/source/isaaclab/isaaclab/managers/reward_manager.py)：框架只乘一次控制dt，本项目reward函数没有再乘一次。没有发现这里存在双乘dt。后续应基于实际奖励分项重平衡，不建议直接猜一组新权重再跑10000轮。

## 3. 已确认：Teacher的臂探索超出当前LL训练工作分布

`paint_locomotion.py::PaintLegPositionAction.apply_actions`在低层训练期间每个物理步都把6个臂关节锁定为默认PD目标。LL虽观察18个关节状态，训练中并没有主动的大范围机械臂动作。

Transport却直接使用`q_des=q0+.5*a_arm`，原始臂动作无额外幅度限制、无目标变化率限制，只受最终关节软限位约束。初始Gaussian std沿用1.0，对应臂目标约0.5rad标准差；同时初始底盘std1.0是小力课程峰值参考0.2的5倍。这是配置中的初始值，不能据此猜测训练末期std。

视频对应的实际臂偏差约1.43rad，明显不同于此前LL评估的约0.07rad量级，构成了实测工作分布差异。Admittance Demo保持默认臂姿态、使用有限幅度的受力响应，因此其稳定不代表当前Teacher的大幅臂运动也被LL覆盖。

建议下一轮先固定臂目标，用已知受力→速度映射或行为克隆建立可用初始高层；再逐步开放小幅臂残差和变化率，并逐项恢复随机化。只需重新训练高层；是否补训LL，应由小幅臂运动下的跟踪结果决定。

## 4. 已确认的几何不一致：载荷高度目标尚未适配GO2

当前高度成本要求箱体相对base的z在0.05–0.25m。读取本仓库真实GO2-PIPER USD的关节局部坐标，沿关节树进行刚体FK，使用默认臂角`[0,.8,-1.2,0,.4,0]`和当前抓取偏移，得到：

- EE相对base高度约0.57846m；
- 箱体相对base高度约**0.51846m**；
- 零关节角FK与USD存储参考变换的最大元素误差约`3.94e-6`，用于校验变换计算。

所以默认携带姿态本身不在高度目标区间。这个核算是USD刚体几何FK，不是服务器PhysX落地后受重力/PD变形的实测高度。MuJoCo对应模型也得到约0.502m，方向一致。

高度代价的权重较小，不能据此断言“大幅摆臂就是高度项单独造成的”。但重训前应先测零动作静态承载高度，再决定GO2的合理高度区间或携带姿态，而非继续直接套用原形态的区间。

## 5. 可确定的监控缺口：倾倒保护被关闭

Transport配置明确设置`terminations.bad_orientation=None`，保留base contact和timeout。严重倾斜只要base尚未接触地面，就可能继续运行；因此“跑满10秒”不等于姿态稳定。9999原生回放中倾角>45°样本占约32%、最大约92°进一步说明需要独立的倾角监控。

是否增加GO2训练的倾角终止、稳定性奖励，应明确作为适配改动；本次没有静默修改终止条件。MuJoCo在约57°时停止与Isaac训练条件本来就不同，不能把窗口快速关闭理解成导出器崩溃。
